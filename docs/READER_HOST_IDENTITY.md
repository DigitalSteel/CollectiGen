# Explicit original-host Reader identity

EncyclopediaInstallation and standalone binding admission have an explicit
schema2_identity=False default. The flag selects supported reference formats;
it grants no root lease, native health or installation authority. Existing
schema1 callers, mappings and binding identity remain compatible. No compiled
profile or normal application factory enables the new mode.

Opted-in observation reads full active references only after original signed
journal/history verification, then rechecks payload/platform and exact saved
selection. Standalone binding requires its original enrollment/trust/root and
bounded independently signed prior history. A saved stage/release digest never
overrides that evidence. connection_from_reference/release convert an already
authenticated identity; they are not proof of signature provenance or ownership.

The installation review, canonical destination, stale review, saved publication
intent, recovery and expected prior selection retain full identity. Original
admission, code-only Data compatibility obligations and recovery scope remain.
An opted-in mismatched saved selection is held rather than reported as complete.
Same-number publication/retry targets cannot be reconstructed from version alone.
Manager settlement compares the entire expected Reader selection and retains its
existing release/inventory, original subject/custody, drain/poll and native-health
checks. Retrying connection publication does not redownload or restage code.

Standalone update observations append release_schema/maturity with legacy
defaults. The new-mode observation token includes current active/journal/settings/
release/selection/trust, original owner generation and current delegation context.
installed_offer_context() is the original host's explicit metadata observer seam;
an opted-in acquisition must be composed with that original observer. Notification
rechecks compare the whole context, without treating its token as a lease.
Pending/unknown/conflicting ownership holds; a running Reader may still receive
notifications where existing policy permits. Replacement requires original normal
Close/drain/exclusion. A schema2 target requires the explicit metadata service.

The Reader helper context retains the exact legacy five strings. Schema2 adds
only release_schema="2", maturity and release_sha256, with strict numeric/stage/
digest validation in the existing Manager helper adapter. This is selected
identity bound to the existing launch attempt, not publisher authentication.
Original typed selection identity, root admission and native custody checks are
unchanged; signed installed state is independently proved by binding.current().

Schema2 acquisition remains unconditionally blocked before refresh/cache/transfer.
Confirmed original requests also appear as pending in the observation; any later
acquisition/revalidation admission must resolve that exact original-request state
without a generic pending bypass. This patch does not qualify a live feed, profile,
flat-root enrollment, actual native/UI/package path or retained rollback archive.
Source fixture tests use injected host crypto/process actors where declared;
metadata signature checks and prior engine qualification remain separate evidence.
Constructor/injected-state checks are component proof, not real entry acceptance.

Connected qualification must retain exact artifacts, visible review/Close/startup,
saved/reopened completion, publication retry, recovery, maturity labels and actual
native custody. Existing data-contract read obligations, root envelope, toolchain,
date and rollback gates remain open. No runnable app version or release tag is
added. Existing licensing applies; scoped source revert retains exact preimages
and never silently rewrites saved identity or Data.
