# Explicit original-host Reader identity

EncyclopediaInstallation and standalone binding admission have an explicit
schema2_identity=False default. The flag selects supported reference formats;
it grants no root lease, native health or installation authority. Existing
schema1 callers, mappings and binding identity remain compatible. No compiled
profile or normal application factory enables the new mode.

Opted-in observation reads full active references only after original signed
journal/history verification, then rechecks payload/platform and exact saved
selection. Standalone binding requires its original enrollment/trust/root and
bounded independently signed prior history. A saved stage/release digest never
overrides that evidence. connection_from_reference/release convert an already
authenticated identity; they are not proof of signature provenance or ownership.

The installation review, canonical destination, stale review, saved publication
intent, recovery and expected prior selection retain full identity. Original
admission, code-only Data compatibility obligations and recovery scope remain.
An opted-in mismatched saved selection is held rather than reported as complete.
Same-number publication/retry targets cannot be reconstructed from version alone.
Manager settlement compares the entire expected Reader selection and retains its
existing release/inventory, original subject/custody, drain/poll and native-health
checks. Retrying connection publication does not redownload or restage code.

Standalone update observations append release_schema/maturity with legacy
defaults. The new-mode observation token includes current active/journal/settings/
release/selection/trust, original owner generation and current delegation context.
installed_offer_context() is the original host's explicit metadata observer seam;
an opted-in acquisition must be composed with that original observer. Notification
rechecks compare the whole context, without treating its token as a lease.
Pending/unknown/conflicting ownership holds; a running Reader may still receive
notifications where existing policy permits. Replacement requires original normal
Close/drain/exclusion. A schema2 target requires the explicit metadata service.

The Reader helper context retains the exact legacy five strings. Schema2 adds
only release_schema="2", maturity and release_sha256, with strict numeric/stage/
digest validation in the existing Manager helper adapter. This is selected
identity bound to the existing launch attempt, not publisher authentication.
Original typed selection identity, root admission and native custody checks are
unchanged; signed installed state is independently proved by binding.current().

Schema2 acquisition remains unconditionally blocked before refresh/cache/transfer.
Confirmed original requests also appear as pending in the observation; any later
acquisition/revalidation admission must resolve that exact original-request state
without a generic pending bypass. This patch does not qualify a live feed, profile,
flat-root enrollment, actual native/UI/package path or retained rollback archive.
Source fixture tests use injected host crypto/process actors where declared;
metadata signature checks and prior engine qualification remain separate evidence.
Constructor/injected-state checks are component proof, not real entry acceptance.

Connected qualification must retain exact artifacts, visible review/Close/startup,
saved/reopened completion, publication retry, recovery, maturity labels and actual
native custody. Existing data-contract read obligations, root envelope, toolchain,
date and rollback gates remain open. No runnable app version or release tag is
added. Existing licensing applies; scoped source revert retains exact preimages
and never silently rewrites saved identity or Data.

## Original launch target projection (B2R1)

The original owner now derives the non-recovery launch target with
connection_from_release from the exact registered confirmed request. Recovery
retains that request's complete saved current selection. Missing, mismatched or
waiting-for-Close requests refuse before reading the offer. Full selection and
release-digest equality precede attempt persistence and actor creation; custody,
Close/drain and native-health gates are unchanged. Legacy four-key selections
remain compatible; schema2 keeps its stage, release digest and exact directory.

Injected boundary tests stop before native creation and exercise legacy/schema2,
target/recovery, changed identity and held ownership. They do not activate schema2
acquisition, compiled profiles or qualify a native/UI/package journey. Reverse
source recovery uses the exact parent and retained patch, without changing Data.

## Original-request metadata-only review (C1A)

ComponentAcquisition.revalidate_exact_metadata(offer, *, check_current,
should_cancel=None) requires explicit metadata mode and a callable. It reuses the
registered original offer, epoch, trust, cache owner, immutable installed context
and stock exact signed metadata selector. Owner checks bracket HTTP; service
identity/cache/trust/cancellation are rechecked after callbacks. Any failure clears
the service's offers and advances its epoch. Success returns None, never an
execution permit, receipt or replacement offer. It reads no artifact/acquired cache
and creates no attempt directory. A caller-provided callback alone proves no lease.

DeploymentOwner.check_standalone_metadata_request(subject, request) checks original
subject/lease/custody, registered request/generation/binding and exact applying
record. No stage or Reader actor/attempt may remain unretired. Current signed
installation/settings must equal the confirmed snapshot. A required normal Close
receipt must still match its original generation, selection, drained phase and
outcome. A fresh already-idle request does not adopt an old Close claim. This
checker never begins/polls an operation, persists a phase or manufactures drain.

StandaloneEncyclopediaBootstrap.revalidate_confirmed_metadata(request, *,
delegate=None) composes the existing acquisition and owner checker. It requires
explicit identity mode and the exact current request; original Manager delegation,
if present, is checked using the existing short scope gate. Fresh full observation
identity fields/token must match the offer's original context, with live pending
remaining True. The acquisition observer must agree with that live observation.
No new root lock spans HTTP; cancellation uses the existing Event. It never calls
apply, acquire, install, profile creation or native launch.

The shared selector now leaves live installed-context publication checks to its
callers: ordinary discover/revalidate still perform them and refuse pending state.
No observer is rewritten and no generic allow-pending mode exists. Schema2 acquire
still refuses unconditionally before refresh/cache/artifact work, even after this
review succeeds with a fake callback. Normal profiles remain inactive.

Signed fake-feed tests and injected original-host crypto/process fixtures qualify
only source behavior. Connected transfer activation, compiled root/child enrollment,
real artifacts/rollback, native/UI/package completion remain separate admission
gates. The next planning boundary is exact original-request acquisition admission;
metadata success cannot substitute for it. No runnable app version is claimed.

## Exact artifact transport scope (C1B1T1)

ReleaseTransportPolicy.schema2_artifact_source optionally accepts one exact stock
ReleaseAssetSource. Type, positive bounded integer size, schema2 first-party URL/
tag/name agreement and non-metadata/non-wildcard name are checked. Artifact mode
is exclusive: only that initial URL is admitted; API, metadata, legacy, alternate
archive/stage/tag/name and direct CDN URLs refuse. Artifact plus metadata mode is
ambiguous and refuses. Existing default and metadata-only policies are unchanged.

ComponentReleaseTransport.for_exact_artifact(source) returns a distinct transport,
policy and redirect handler. It copies only already-validated redirect origins
and hop bound, not metadata mode, an old scoped source/opener, credentials or
global opener state. Existing GET/credential/timeout/redirect restrictions apply;
unqualified origins still refuse, and constructing a transport performs no HTTP.

The source DTO's size/api_digest and URL are not signature, lease, acquisition or
installation authority. The original host must separately prove its exact request,
signed source binding, cache/file hashes and original installation admission.
This factory is not wired into acquisition, installation or a compiled profile.
Ordinary acquire(schema2) remains held. C1B1's unpublished handoff still needs
reconciliation with this accepted transport and complete refusal/recovery checks.
Contained policy/opener tests qualify source only; no real CDN, artifact, rollback,
toolchain, native/UI/package or production execution admission is implied.

## Original-request acquisition and installer handoff (C1B1)

StandaloneEncyclopediaBootstrap.apply_confirmed_metadata(request, *, progress=None,
delegate=None) is an explicit original-host source route. It requires the exact
retained request, original subject/owner/binding/acquisition/installer/delegate,
explicit identity/metadata mode and original custody. A waiting request begins
once after Close/drain; an already-applying request continues without beginning
again. Other or changed requests/installed snapshots refuse. No profile enables
this entry automatically, and ordinary acquire(schema2) remains held.

The service-private acquisition path reuses C1A fresh metadata and the existing
bounded cache/download/hash/cleanup kernel. Schema2 uses T1's exclusive exact-asset
opener in an ephemeral stock downloader; the metadata opener stays unchanged.
Legacy acquisition retains its normal path. Signature revalidation includes exact
maturity. Cache hits still revalidate metadata, ownership and file bytes. Cache
root/marker/owner identity stays bound to construction; changed ownership forbids
foreign cleanup. Owner/epoch/trust/cache/cancellation checks repeat after callbacks,
download and hashing. None of these DTOs or callbacks independently grants a lease.

The original bootstrap retains the exact acquired result. The private installer
handoff binds that object to its original host check, consumes the original review
once and rejoins the same installation body; no ordinary acquisition/network review
is repeated. Local review, current signed selection/settings/destination and named
Data compatibility stay checked. Shared request/custody/Close checks run in the
existing component scope; no-stage/baseline metadata checks remain outside it.
Pre-install baseline checks occur before mutation, not successful publication exit.
No root or maintenance lock spans HTTP. Stop, unchanged-baseline abandonment,
partial publication, Retry save and explicit recovery retain their existing owners.

Source fixtures cover waiting/continuation, one transfer and fresh cache hits,
same-number stage publication, changed/reconstructed inputs, cancellation, foreign
cache retention, saved publication retry and original recovery. Host crypto/process
and HTTP delivery are injected where declared; separate acquisition tests use real
fixture signatures. These are source/component results, not native/UI/package proof.

The existing stager still refuses a legacy prerelease exactly on a numeric floor
that metadata ordering admits; the explicit supported_component_floor refusal is
retained under follow-up F. This patch changes no staging-floor rule and does not
claim every displayed metadata offer is installable. Actual signed production
artifacts/CDN/rollback, compiled root/profile/toolchain, real visible/saved/native/
package acceptance remain open. No runnable application version is claimed.
