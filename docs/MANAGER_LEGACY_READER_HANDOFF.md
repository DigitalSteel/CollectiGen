# Manager legacy Reader handoff

The local Manager 0.6.0 Alpha candidate reuses the unchanged signed public Reader 0.2.2 standalone launcher. Manager closes normally and releases its deployment lease before the launcher starts. The original outer supervisor retains the exact process, non-killing Windows Job and output drain. Manager returns through a fresh ordinary admission only after the complete launcher scope retires. Unknown closure remains held; no process is adopted by PID and no health receipt is fabricated.

Preparation mirrors only the reviewed Reader connection using the existing stale-guarded writer. Explicit commit records a fixed deployment-local selection authority. Cancellation removes only that request's newly created pointer. Legacy-origin installations continue through the shared launcher after updating to public Reader 0.3.1, preserving the Reader connection and catalog bytes through usable rollback. Catalog browsing was verified by explicitly opening the synthetic catalog after each launch. Fresh Reader 0.3.1 installations keep their existing launch route.

Runtime owners: core/encyclopedia_legacy_handoff.py (selection transaction), core/encyclopedia_legacy_host.py (authenticated Root admission), suite_core/manager/legacy_reader_handoff_ui.py (review and progress), suite_core/manager/legacy_reader_supervisor.py (original native scope), and launcher_main.py (serial restart). Build inclusion and signed archive verification belong to tools/build_manager_distribution.py. Focused tests cover cancellation, replay, stale guards, original birth reconciliation, retirement and exact package mapping.
