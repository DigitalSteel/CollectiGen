# Encyclopedia qualification build preparation

These files prepare a separate, pinned source stage and two onedir recipes for
Tag Encyclopedia. They do not build, launch, sign, install or update an app.
Source `bootstrap_entry.PROFILE` remains inactive. A generated bound profile is
restricted to one fresh disposable qualification root and sealed local responses.

The stage reuses `tools/build_manager_distribution.py` source, path and pin
validators and `tools/manager_build/windows_build_isolation.py` graph and binary
guards. It does not reuse the Manager-specific entries, manifest, SDK or bundle
identity. The existing `tools/build_component_package.py` remains the packaging
owner for an already frozen reader payload, including its update data contract.

## Inputs and preparation

The coordinator must first review and enroll the new files in the accepted public
source export and test/map registries. Supply an accepted export containing its
`public-source.json`, a reviewed finite frozen-source subset with exact path,
byte-size and SHA-256 rows, the exact component manifest pin, and a public
toolchain input. The stager validates every input before creating a fresh output.

The toolchain schema is `schema: 1`,
`purpose: ENCYCLOPEDIA_QUALIFICATION_BUILD_ONLY`, with `platform`, `python`,
`distributions` and `build_inputs`; consult `validate_toolchain` for the exact
fields. Interpreter bytes/hash/version and every wheel version are explicit.
Python must be Windows x64 CPython 3.13 or 3.14 with matching ABI. Required wheels
are PyInstaller, PySide6 Essentials and shiboken6. This input declares reviewed
requirements; it does not establish that the running environment satisfies them.

`build_inputs` pins seven repository files: the two specs, recipe support,
profile renderer, stager, stock Manager build validators and stock Windows build
isolation. The loaded renderer and stager must match those accepted bytes too.
The executing stock validators and the data-contract/signature-version validators
must also match their accepted public-source bytes before project validation is
called. This bootstrap admission uses standard-library path and digest checks.
Five build inputs are copied to the stage; the renderer creates the explicit
generated rows. Generated rows are distinguished from accepted source rows.

Run preparation from the repository root, replacing every placeholder with an
explicit reviewed path or pin:

```powershell
.venv\Scripts\python.exe -B -m tools.prepare_encyclopedia_qualification_stage `
  --source-root <accepted-export> --output <fresh-output> `
  --public-inventory-sha256 <inventory-sha256> `
  --frozen-sources <reviewed-subset.json> --frozen-sources-sha256 <subset-sha256> `
  --module-sha256 <module-sha256> `
  --toolchain <reviewed-toolchain.json> --toolchain-sha256 <toolchain-sha256>
```

Without a fixture profile, generated entries hold immediately. To prepare a bound
qualification stage, add `--fixture-profile <sealed-profile.json>` and
`--fixture-profile-sha256 <profile-sha256>`. The exact schema is documented by
`PROFILE_FIELDS` and `validate_profile`: schema/purpose, absolute fresh fixture
root, Data/settings/cache relative paths, public trust bytes encoded as hex and
their SHA-256, sealed response-map SHA-256, channel and host version. Private key
fields are refused. The fixture root must not exist or overlap the accepted
source root. No fixture files or signatures are generated by preparation.

Record the resulting `stage/STAGE.json` SHA-256. Before any separately authorized
freeze, verify exact membership and bytes:

```powershell
.venv\Scripts\python.exe -B -m tools.prepare_encyclopedia_qualification_stage verify-stage `
  --stage <fresh-output>/stage --stage-sha256 <stage-sha256>
```

## Later freeze and admission

For bounded component packages, preparation may explicitly select
`--compiled-sources-only`. Source pins and all Analysis/origin checks remain;
datas contain only non-Python resources. The recipe then requires static PYZ
readback equivalent to every pinned Python source (including nested code and
typed recursive constants and float bit patterns, allowing only relocated
filenames), plus full actual CArchive startup-script comparison to the pinned
selected entry source. The default retains source copies.
This avoids exceeding the stock 512-file package bound with redundant `.py` datas;
it does not relax the packager or qualify runtime behavior.

A separately authorized build uses the admitted native interpreter and unchanged
stage. The recipes check actual interpreter bytes, architecture/version and wheel
versions before Analysis. Run each role sequentially with fresh work/dist paths:

```powershell
<admitted-python.exe> -I -B -m PyInstaller --noconfirm `
  --distpath <fresh-reader-dist> --workpath <fresh-reader-work> `
  <fresh-output>/stage/TagEncyclopediaReader.spec
<admitted-python.exe> -I -B -m PyInstaller --noconfirm `
  --distpath <fresh-root-dist> --workpath <fresh-root-work> `
  <fresh-output>/stage/TagEncyclopediaRoot.spec
```

Both bundles contain `TagEncyclopedia.exe`; the root image belongs at the fixed
installation root, and a reader belongs under its versioned
`Apps/collectigen.tag-encyclopedia` slot. The root image also runs the custody
role. Preserve each onedir `_internal` payload and required license notices.
The existing-system MSVC prerequisite remains explicit; recipes do not install
dependencies. Actual analysis closure, PE/binary inventory, package/data-contract
validation and admitted runtime behavior are still required. A finite source
inventory or synthetic constructor test is not freezer qualification. The stager
records repository namespaces from the accepted public inventory independently
of runtime/subset filtering; recipes require that registry and also retain
component-declared namespaces. Every collected local module must resolve to its exact
admitted stage path and byte pin; outside-stage resolutions hold.
For a PyInstaller namespace package without `__init__.py`, the recipe instead
requires the actual namespace node, its single exact staged directory and pinned
descendant source rows. Merged or outside-stage namespace paths hold.
Lazy core-facade attribute warnings resolve only through the pinned literal export
map to an already collected, pinned owner declaring the exact symbol. Unknown
attributes and absent owners remain missing-module holds.

No admissible signed Windows Encyclopedia A/B payload set was established by
this source slice. The fixed public Linux signature vector tests signature
verification, but cannot admit a Windows executable replacement. An existing
approved manifest/signature/public-trust set must match the actual built Windows
artifacts before native installation/update acceptance. No keys, signatures or
production signer access are created here.

Remaining native acceptance includes first enrollment, original root custody and
single-owner conflicts with Manager, reader READY rights, A/B/A update/recovery,
root loss at enrollment/birth/in-flight operation, acknowledgment and descriptor
closure, final Job closure and durable receipt. The coordinator owns shared
entry/supervisor integration and records each observed level separately.
